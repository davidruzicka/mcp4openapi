## Decisions Made

- **CHANGELOG consolidation, not duplication.** The plan acceptance criterion required `grep -c "Encrypted token envelopes" CHANGELOG.md` to return exactly 1. Pre-existing CHANGELOG had two plan-internal entries (one for Plan 01's crypto module, one for Plan 03's HTTP transport wiring) added during their respective plans. Both were narrowly worded from a developer/internal perspective. Plan 04 explicitly required a single user-perspective line per AGENTS.md "Always compress lines"; the right move was to replace both prior bullets with one consolidated line, not append a third. From the user perspective there is one feature, not three.
- **MCP4_TOKEN_MAX_LENGTH default bump in scope.** The plan explicitly listed updating the README's `MCP4_TOKEN_MAX_LENGTH` default from `1000` to `4096` as part of this task. Plan 03 raised the runtime default but documentation drifted. Even though it is technically a Plan 03 documentation gap, this plan owns README.md edits and the change is one-line and entirely within the same area being touched, so folding it in was the cleanest resolution.
- **Section depth in HTTP-TRANSPORT.md.** The plan's anchor description called out that the new section should sit "near 'Session Management'" and that 'Session Storage' is the immediate predecessor. Inspection of the file confirmed `## Session Management`, `### Session Storage`, `## SSE Resumability` - so the new section uses `##` (top-level) to match `Session Management` / `SSE Resumability`, not `###` like the `Session Storage` subsection. Three new content subsections inside (`### Token format`, `### When envelopes are issued`, etc.) use `###` to match the pre-existing depth pattern.
- **Comment text in env.example uses ASCII commas instead of em/en dashes.** AGENTS.md "Avoid" forbids U+2014 and U+2013 anywhere in code or docs. The single-line comment that the plan provided uses commas and ASCII hyphen-minus throughout - verified post-edit with the `LC_ALL=C grep` invocation.
- **client_secret mentioned exactly where required.** The plan's acceptance criterion required at least one `client_secret` match in HTTP-TRANSPORT.md to document the security boundary explicitly. The Token format subsection includes the line "`client_secret` is NEVER embedded - DCR clients are public PKCE clients without one." This is the only place client_secret appears in the new content; pre-existing references in env.example (`#MCP4_OAUTH_CLIENT_SECRET=...`) and README.md (`export MCP4_OAUTH_CLIENT_SECRET=...`) are unrelated DCR setup and were not touched.
