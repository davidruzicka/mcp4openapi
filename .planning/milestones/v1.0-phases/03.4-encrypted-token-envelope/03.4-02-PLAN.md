<objective>
Wire the `MCP4_OAUTH_KEY` environment variable into `HttpTransportConfig` so Plan 03 (and future
phases) can read `this.config.tokenKey` to encrypt/decrypt token envelopes. Plan 03 will also
emit a startup warning when this field is undefined.

Purpose: Decouple env-var reading (a side effect) from the pure crypto module shipped in Plan 01.
The config layer is the canonical entry point for all `MCP4_*` settings - adding token-key
parsing here keeps the architecture consistent with maxTokenLength, oauthSessionTimeoutMs, etc.

Output: A single optional `tokenKey?: Buffer` field on `HttpTransportConfig`, populated by
`buildHttpTransportBaseConfig()` from `process.env.MCP4_OAUTH_KEY` via `deriveTokenKey()`.
Tests cover unset, 64-char hex, passphrase, and whitespace-trim cases.
</objective>
