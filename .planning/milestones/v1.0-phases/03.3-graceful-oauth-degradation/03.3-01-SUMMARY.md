# Phase 03.3 Plan 01: isOAuthConfigOperational pre-flight check Summary

One-liner: OAuth pre-flight gate with env-var resolution that returns operational status without throwing, enabling graceful degradation before ExternalOAuthProvider construction.

## What Was Built

Added three new constructs to `src/auth/oauth-provider.ts`:

1. **`tryResolveEnvRef(value)`** - module-private function that safely resolves `${env:VAR}` references returning `undefined` (not throwing) when a referenced env var is absent. Literal values pass through unchanged.

2. **`OAuthOperationalCheck`** - exported interface: `{ operational: boolean; missing: string[] }`.

3. **`isOAuthConfigOperational(config)`** - exported function performing a pre-flight check on an `OAuthConfig`. Checks (after env-var resolution):
   - `issuer` OR (`authorization_endpoint` AND `token_endpoint`) is present
   - `redirect_uri` is present, unless `allow_unregistered_clients: true`

   Returns `{ operational: false, missing: [...] }` for any absent/unresolved field; `{ operational: true, missing: [] }` when all required fields are resolvable.

## Tests Added

11 parametrized test cases in `src/auth/oauth-provider.test.ts` under `describe('isOAuthConfigOperational')`:

- Complete config with issuer + redirect_uri -> operational=true
- Complete config with explicit endpoints + redirect_uri -> operational=true
- Empty config -> operational=false, both fields in missing[]
- Issuer only (no redirect_uri) -> operational=false, missing=['redirect_uri']
- allow_unregistered_clients=true without redirect_uri -> operational=true
- Unset issuer env var -> operational=false
- Set issuer env var -> operational=true
- Unset redirect_uri env var -> operational=false
- Set redirect_uri env var -> operational=true
- Only authorization_endpoint (no token_endpoint) -> operational=false
- (via it.each table) all 5 parametrized cases
