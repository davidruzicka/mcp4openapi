## Verified End-to-End Behavior

Raw HTML pass-through chain (full path from env var to rendered HTML):

1. **Admin env var** `MCP4_PROFILES_DESCRIPTION='{"gitlab":"<a href=\"https://x.example/\">link</a>"}'`
2. **parseProfilesDescriptionEnv** → `Map { 'gitlab' => '<a href="https://x.example/">link</a>' }`
3. **resolveProfileAdminDescriptions** → resolves against profile list → same map (key matches)
4. **HttpTransport.setProfileAdminDescriptions** → stored as `Map<string,string>`
5. **buildProfileIndexPayload** → `enriched.adminDescription = '<a href="https://x.example/">link</a>'`
6. **safeJsonForHtml(enriched)** → `"adminDescription":"<a href=\"https://x.example/\">link</a>"` (ALL `<` escaped to `<`, `>` left as `>`, `"` escaped to `\"` by JSON)
7. **renderProfileIndexHtml** → replaces `{{profile_data}}` with that JSON string verbatim inside `<script type="application/json">` tag
8. **Client-side renderDetail** → reads `profileData` parsed from JSON → `profile.adminDescription = '<a href="https://x.example/">link</a>'` → raw interpolation into innerHTML → browser renders a clickable link

The test assertion `expect(rendered).toContain('\\u003ca href=\\"https://x.example/\\">link\\u003c/a>')` verifies step 7: the rendered HTML string contains the literal `<a href=\"https://x.example/\">link</a>` — no `&lt;`, no `&amp;`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Test 1 assertion corrected for actual safeJsonForHtml behavior**
- **Found during:** Task 2 (GREEN phase — test was failing)
- **Issue:** Plan's test specification wrote the expected assertion as `'\\u003ca href=\\"https://x.example/\\"\\u003elink\\u003c/a\\u003e'` which at runtime translates to `<a href=\"https://x.example/\">link</a>`. However, `safeJsonForHtml` only escapes `<` to `<`, NOT `>`. The actual rendered string has literal `>` for tag closings: `<a href=\"https://x.example/\">link</a>`.
- **Fix:** Updated assertion to `'\\u003ca href=\\"https://x.example/\\">link\\u003c/a>'` which correctly reflects that `>` is not escaped
- **Files modified:** `src/transport/profile-index.test.ts`
- **Commit:** `8770625`

Note: This is the same class of bug that occurred in Plan 02 Task 1 (where the plan's comment said "safeJsonForHtml only escapes `</`" but it actually escapes all `<`). The Plan 03 spec attempted to correct this but overcorrected — it correctly stated `<` is escaped but then also escaped `>` in the expected string, which `safeJsonForHtml` does not do. Corrected inline.
