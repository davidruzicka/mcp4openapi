# Phase 03.3 Plan 02: Wire isOAuthConfigOperational into transport and resolver Summary

One-liner: OAuth graceful degradation wired into HTTP transport auth gate (oauthDisabledReason + ProfileRuntimeState) and profile-resolver (extractAuthMethods filtering), with full test coverage and backward-compatible fixture fixes.

## What Was Built

### Task 1: oauthDisabledReason in ProfileRuntimeState + auth gate guard (src/transport/http-transport.ts)

- Added `oauthDisabledReason?: string` field to `ProfileRuntimeState` interface with explanatory comment
- Added `isOAuthConfigOperational` to the existing import from `oauth-provider.js`
- In `getProfileState()`, replaced the bare `new ExternalOAuthProvider(...)` call with a pre-flight check:
  - Calls `isOAuthConfigOperational(context.oauthConfig)` before constructing the provider
  - If `!operational`: sets `oauthDisabledReason`, skips constructor
  - If `operational`: constructs provider inside try/catch (edge-case guard for env var changes between check and construction)
  - Emits `logger.warn('OAuth config not operational - OAuth disabled for profile', ...)` when degraded
- The `oauthDisabledReason` is stored in the `ProfileRuntimeState` object literal
- Auth gate at line ~2802 changed from:
  ```
  if (effectiveAuthContext.oauthConfig && !authInfo.token)
  ```
  to:
  ```
  if (effectiveAuthContext.oauthConfig && !profileState.oauthDisabledReason && !authInfo.token)
  ```

### Task 2: OAuth filtering in extractAuthMethods (src/profile/profile-resolver.ts)

- Added `OAuthConfig` type import and `isOAuthConfigOperational` import
- Inside `extractAuthMethods()` loop, after the type guard, added a check for oauth entries:
  - Extracts `oauth_config` via safe property access (`(record as unknown as { oauth_config?: OAuthConfig }).oauth_config`)
  - Calls `isOAuthConfigOperational` and skips the entry with `continue` when `!operational`
  - Falls through normally when config is absent (minimum field validation done at load time)

### Task 3: Tests for degradation path

**profile-resolver.test.ts:**
- Updated existing test `'extracts env vars and auth methods for profile index'`: removed OAuth from expected authMethods (the test uses unresolved env var + no redirect_uri, so OAuth is now correctly filtered)
- New test `'filters OAuth from authMethods when oauth_config has unresolved env var'`: asserts OAuth absent, bearer/custom-header present, oauthEnvVars still collected
- New test `'keeps OAuth in authMethods when oauth_config is complete (redirect_uri set, env vars resolved)'`: asserts OAuth IS present with resolved env var + redirect_uri

**profile-index.test.ts:**
- New test `'does not emit oauth authTab when OAuth is not in authMethods (operationally degraded)'`: builds a ListedProfileDetails with no oauth entry in authMethods, asserts no oauth authTab and bearer authTab is present

**http-transport.test.ts:**
- New test `'sets oauthDisabledReason and leaves oauthProvider null when oauth config is missing redirect_uri'`: creates transport with incomplete config, calls getProfileState, asserts oauthProvider is null, oauthDisabledReason contains 'redirect_uri', hasOAuthProvider() returns false, and logger.warn was called
- Fixed 3 existing OAuth test fixtures in hasOAuthProvider/getOAuthAuthorizationUrl/getOAuthScopes describes that were missing redirect_uri

**http-transport-security.test.ts:**
- Fixed 10 existing test fixtures missing redirect_uri (tests that call handlers directly without createProfileState mock injection)
