## Exact ValidationError Messages Introduced

- Array JSON in env var: `"{envVarName} must contain a single JSON object, not an array. Change [{...}] to {...}"`
- Non-object JSON in env var: `"{envVarName} must contain a JSON object"`
- Invalid transport URL: `"upstream_mcp.transport.url must be a valid absolute URL"` (no `[0]` index)
- Missing header_name: `"upstream_mcp.auth.header_name is required for custom-header auth"`
- All `validateUpstreamProvider` error paths now use `upstream_mcp.subfield` format (not `upstream_mcp[0].subfield`)

## Schema Rejection Behavior (D-03 / Zod)

When a profile YAML/JSON contains `upstream_mcp: [{...}]` (array syntax), the generated Zod schema
throws `ZodError` (not `ValidationError`) with:
```
Expected object, received array at path: ["upstream_mcp"]
```
This fires at `enhancedProfileSchema.parse(json)` in ProfileLoader.load(), before any loader runtime checks.

## Decisions Made

- `ZodError` (not `ValidationError`) is the correct assertion for tests checking array rejection at the schema layer — Zod's `parse()` throws before loader runtime guards fire.
- `upstream_mcp: []` (empty array) also throws `ZodError` with "Expected object, received array" — Zod rejects arrays regardless of content.
- `validateUpstreamProvider` path changed from `upstream_mcp[${index}]` to `upstream_mcp` — all error paths are now `upstream_mcp.transport.url`, `upstream_mcp.auth.header_name`, etc.
