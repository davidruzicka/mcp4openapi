# Phase 03.1: Odstranění multi upstream mcp supportu - Context

**Gathered:** 2026-05-02
**Status:** Ready for planning

<domain>
## Phase Boundary

Refactor `upstream_mcp` from `UpstreamMcpServerConfig[]` (array) to `UpstreamMcpServerConfig`
(singular) across all layers: TypeScript types, generated Zod schemas, the config resolver,
all downstream call sites, and tests.

Profile-loader D-03 already enforces the single-upstream constraint at runtime. This phase
makes the types and code match that constraint end-to-end: no more `[0]` index access,
`?.length &&` guards, or `for...of` loops over a one-element array.

No behavior change for correctly-configured profiles. Breaking change only for profiles
using array syntax (they must migrate to object syntax).

</domain>

<decisions>
## Implementation Decisions

### upstream_mcp_from_env JSON format

- **D-01:** After the type change, `upstream_mcp_from_env` must contain a single JSON **object**
  (`{name: ..., transport: ...}`), not an array. An array value produces a `ValidationError`
  with a clear migration message: "upstream_mcp_from_env must contain a single JSON object,
  not an array. Change [...] to {...}". `parseUpstreamMcpJson` becomes a simple
  `JSON.parse` + Zod schema validation with no array-handling branch.

### name field

- **D-02:** The `name` field is **kept** on `UpstreamMcpServerConfig`. It is still useful for
  structured log fields, error messages, and the connection manager dedup key. No type change
  needed on `UpstreamMcpServerConfig` itself beyond removing it from an array context.

### Profile config migration (breaking change)

- **D-03:** Existing YAML/JSON profiles using array syntax (`upstream_mcp: [{...}]`) receive a
  hard `ValidationError` after the schema change: "upstream_mcp must be a single object, not
  an array. Change `upstream_mcp: [{...}]` to `upstream_mcp: {...}`". No silent coercion.
  The error must fire at profile load time (schema validation catches it before D-02/D-03
  runtime checks).

### Connection manager key scheme

- **D-04:** The `UpstreamConnectionManager` dedup key stays `${sessionId}:${provider.name}`.
  No changes to connection manager internals. The `name` field on the single config satisfies
  the key requirement at zero additional cost.

### Downstream call site cleanup

- **D-05:** All `?.length &&` guards on `upstreamMcp` change to direct presence checks
  (`upstreamMcp &&`). All `[0]` index accesses change to direct property access.
  The single `for...of` loop in `http-transport.ts:2865` changes to a direct call using
  the singular config value.

### Schema regeneration

- **D-06:** After changing `upstream_mcp` in `src/types/profile.ts` from
  `UpstreamMcpServerConfig[]` to `UpstreamMcpServerConfig`, run `npm run generate-schemas`.
  The `generated-schemas.ts` field changes from `z.array(upstreamMcpServerConfigSchema)` to
  `upstreamMcpServerConfigSchema`. Do NOT manually edit `generated-schemas.ts`.

### Profile-loader D-03 check removal

- **D-07:** The existing D-03 runtime check in `profile-loader.ts` (rejects `> 1 providers`) is
  removed. The Zod schema change makes it impossible to even parse an array value as a
  valid config, so the runtime check becomes dead code. D-02 check (`?.length &&`) also
  simplifies to a direct presence check.

### Claude's Discretion

- Error message exact wording — follow the style established in existing ValidationError
  messages in the codebase (lowercase, descriptive path, no period at end).
- Test helper function `makeProfile(upstream_mcp: unknown[])` in upstream-mcp-config.test.ts —
  update signature to accept singular object; update all test fixtures accordingly.
- `upstream_mcp_from_env` test cases that pass array JSON — update to pass object JSON and
  add one negative test confirming array input errors.

</decisions>

<specifics>
## Specific Ideas

- The `validateUpstreamProvider` error path prefix changes from `upstream_mcp[${index}]`
  to just `upstream_mcp` — e.g., `upstream_mcp.transport.url` instead of
  `upstream_mcp[0].transport.url`. This affects error message strings in tests.
- Existing test case "rejects profile with more than one provider" (profile-loader.test.ts:3341)
  becomes a schema-level error test (Zod rejects array before loader validation runs).
- `HttpProfileContext` comment on line 112: "Upstream MCP providers for single-profile mode" —
  update comment to "Upstream MCP provider for this profile" after type change.
