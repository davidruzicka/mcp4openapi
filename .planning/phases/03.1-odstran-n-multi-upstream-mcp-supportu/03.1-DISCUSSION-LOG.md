## upstream_mcp_from_env JSON format

| Option | Description | Selected |
|--------|-------------|----------|
| Object only: `{name: ..., transport: ...}` | Clean break. env var must be a single JSON object. Array syntax errors with a clear message. Simplest code path — parseUpstreamMcpJson becomes just JSON.parse + schema validate | ✓ |
| Object or single-element array | Backward compat: `[{...}]` auto-coerces to `{...}`. Multi-element array still errors. Extra branch in parseUpstreamMcpJson | |
| You decide | Let planner choose based on code simplicity | |

**User's choice:** Object only — clean break, simplest code path.

## name field fate

| Option | Description | Selected |
|--------|-------------|----------|
| Keep name | Low-risk, stays in logs and connection key. Connection manager key remains sessionId:providerName — zero logic change needed there. Also useful for future tool_prefix and policy references | ✓ |
| Remove name | Cleaner type — one less required field. But ripples through connection manager, logs, error messages, tests. Higher blast radius for a refactor phase | |
| Make name optional | Keep for logging if provided, auto-generate (e.g. from profile_name) if absent. Middle ground but adds fallback logic | |

**User's choice:** Keep name — low blast radius, still useful for logs and connection key.
