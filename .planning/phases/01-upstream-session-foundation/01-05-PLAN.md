    - validateCredentials(sessionId, provider, undefined) with validation_endpoint: resolves without error (no token to validate)
    - validateCredentials(sessionId, provider, 'valid-token') with validation_endpoint returning 200: resolves without error
    - validateCredentials(sessionId, provider, 'bad-token') with validation_endpoint returning 401: throws UpstreamAuthError
    - validateCredentials(sessionId, provider, 'bad-token') with validation_endpoint returning 403: throws UpstreamAuthError
    - validateCredentials with validation_endpoint that times out: throws UpstreamTimeoutError
    - validateCredentials with validation_endpoint that network-errors: throws UpstreamConnectionError (not UpstreamAuthError)
    - validation_method defaults to 'HEAD' when not specified
    - validation_timeout_ms defaults to 5000 when not specified
  </behavior>
  <action>
    UAT Gap 3: "No early auth validation at session init - upstream token validity only surfaces on first tool call. User suggests validation_endpoint variant in mcp profile."

    Reference model: The inbound AuthInterceptor.validation_endpoint already exists in profile types.

    1. Add fields to `UpstreamMcpServerConfig` in `src/types/profile.ts`:
       ```typescript
       /** Optional endpoint to validate upstream credentials at session init (fail-fast). */
       validation_endpoint?: string;
       /** HTTP method for validation probe. Default: 'HEAD'. */
       validation_method?: 'HEAD' | 'GET';
       /** Timeout for validation probe in ms. Default: 5000. */
       validation_timeout_ms?: number;
       ```
       Place these after the `timeout_ms` field.

    2. Write tests FIRST in `src/upstream/upstream-connection-manager.test.ts`:
       - Create a new `describe('validateCredentials', ...)` block
       - Mock global `fetch` using `vi.stubGlobal('fetch', vi.fn())` for each test
       - Test: no validation_endpoint configured -> resolves without calling fetch
       - Test: no token -> resolves without calling fetch
       - Test: fetch returns 200 -> resolves without error
       - Test: fetch returns 401 -> throws UpstreamAuthError with provider name
       - Test: fetch returns 403 -> throws UpstreamAuthError
       - Test: fetch rejects (network error) -> throws UpstreamConnectionError
       - Test: fetch aborts (timeout via AbortSignal.timeout) -> throws UpstreamTimeoutError
       - Test: validation_method defaults to 'HEAD', respects 'GET' override
       - Test: validation_timeout_ms defaults to 5000, respects override
       - Restore fetch mock after each test with `vi.restoreAllMocks()`

    3. Add `validateCredentials` method to `UpstreamConnectionManager` in `src/upstream/upstream-connection-manager.ts`:
       ```typescript
       /**
        * Opt-in early auth validation against upstream validation_endpoint.
        * Performs a lightweight HTTP probe to verify token is accepted.
        * No-op when validation_endpoint is not configured or token is absent.
        */
       async validateCredentials(
         sessionId: string,
         provider: UpstreamMcpServerConfig,
         token: string | undefined,
       ): Promise<void>
       ```
       Implementation:
       - If `!provider.validation_endpoint || !token` -> return (no-op)
       - Build auth headers using `buildAuthHeaders(provider, token)`
       - Use native `fetch` with:
         - `method: provider.validation_method ?? 'HEAD'`
         - `headers: authHeaders`
         - `signal: AbortSignal.timeout(provider.validation_timeout_ms ?? 5000)`
       - On response: if `response.status === 401 || response.status === 403` -> throw new `UpstreamAuthError(provider.name)`
       - On AbortError/TimeoutError: throw new `UpstreamTimeoutError(provider.name, provider.validation_timeout_ms ?? 5000)`
       - On other fetch error: throw new `UpstreamConnectionError(sanitizeAuthErrorMessage(err.message), provider.name)`
