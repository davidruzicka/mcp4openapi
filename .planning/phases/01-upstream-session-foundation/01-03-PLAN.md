<objective>
Implement application-level heartbeat pings for upstream MCP connections to detect silent SSE disconnects before tool calls fail.

Purpose: Intermediate proxies (nginx, cloud LBs) silently close idle SSE connections after 60-120 seconds. Without app-level heartbeats, the gateway only discovers the broken connection when a tool call fails. The heartbeat manager pings at configurable intervals and triggers a failure callback when the upstream stops responding (REL-01). This also supports REL-02 (reaper can check connection health) and REL-03 (heartbeat failures produce typed errors).

Output: UpstreamHeartbeatManager class with configurable interval/timeout, failure callbacks, and cleanup. Full test coverage with fake timers.
</objective>

         - Private `timers: Map<string, NodeJS.Timeout>` keyed by `${sessionId}:${providerName}`
         - `start(key: string, pingFn: () => Promise<void>, onFailure: (error: Error) => void): void`
           - If timers.has(key), return (idempotent)
           - `const timer = setInterval(async () => { try { await pingFn(); } catch (error) { onFailure(error instanceof Error ? error : new Error(String(error))); } }, this.config.intervalMs)`
           - Store timer in timers map
         - `stop(key: string): void`
           - Get timer from map, clearInterval, delete from map
           - No-op if not present
         - `stopAll(): void` - stop all active timers
         - `isRunning(key: string): boolean` - return timers.has(key)
         - `getActiveCount(): number` - return timers.size

       Note: The ping timeout is handled by the caller passing `() => client.ping({ timeout: config.timeoutMs })` as the pingFn. The heartbeat manager does not need to implement its own timeout - it delegates to the MCP SDK's built-in timeout support. This keeps the manager simple and testable.
